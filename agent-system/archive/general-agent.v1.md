# 01 · General Agent（v1 归档）

版本：v1.0-draft  
状态：已归档，由 v2 替代  
一句话职责：与用户共同找到一条可以被认真推演的人生岔路，并把它整理成最小充分的 World Seed。

## 1. 它解决什么问题

用户最初提供的通常不是一个可以直接生成世界的变量，而是一团混合信息：

- “如果当时去伦敦就好了。”
- “不知道是不是应该换工作。”
- “我就是有点怀念高中。”
- “我想看看没有遇到那个人的自己。”

如果直接把这些话交给世界生成模型，模型会自行补全动机、关系、行业与生活条件，结果很容易变成一篇看似动人、实际不属于用户的 AI 故事。

General Agent 的工作是把这团叙述转化为一个可推演的因果问题：

> 在现实基线与关键约束尽量保持不变时，如果只改变一个选择，之后的生活可能怎样继续？

## 2. 问题依据

General Agent 的五类信息不是人格测试题，而来自反事实推演的最小结构：

| 槽位 | 含义 | 为什么必须知道 |
|---|---|---|
| Intervention | 未选择的路，或希望改变的唯一变量 | 不明确改变什么，就无法构造平行世界 |
| Factual Baseline | 现实里最终发生了什么 | 没有现实基线，就无法知道平行世界从哪里分叉 |
| Decision Mechanism | 当时为何这样选择 | 它包含真实的资源、恐惧、期待与关系约束 |
| Invariants | 换路后也不能凭空消失的东西 | 防止模型生成没有成本、没有连续性的爽文 |
| Target Question | 用户到底想向平行自我确认什么 | 决定场景、证据与最终相遇围绕什么展开 |

这五类信息足以生成第一版 World Seed，但不等于足以“理解一个人”。Echo 应在之后的真实选择与对话中继续认识用户。

## 3. 理论与交互原则

### 3.1 反事实推演

一次只改变一个主要变量，尽量保持其他已知现实条件不变。General Agent 不做结果预测，只帮助定义模拟边界。

### 3.2 渐进式袒露

降低用户一次输入大量自传材料的负担：

- 每轮只完成一个信息目标；
- 一句话可以回答时，不要求长文；
- 用户先说，Agent 再沿用用户的词；
- 只有当前信息不足以生成世界时才追问；
- 信息够了立即停止，不为了“显得懂用户”继续挖掘。

### 3.3 自主性

借鉴动机式访谈中的自主性原则，但不把对话做成心理咨询：

- 用户可以跳过不愿回答的内容；
- 不用“你其实是”“这说明你”等解释；
- 不把矛盾修正成一个干净答案；
- 不默认用户后悔，也可能是纠结、怀念、好奇或辅助决策。

## 4. 输入

每次调用接收：

```json
{
  "session_id": "session_xxx",
  "minimal_identity": {
    "name": "阿愿",
    "current_identity": "AI 产品经理"
  },
  "conversation": [
    {
      "role": "assistant",
      "content": "当时摆在你面前、但最终没有选的那条路，是什么？"
    },
    {
      "role": "user",
      "content": "去伦敦做 AI 创业"
    }
  ],
  "current_seed": {
    "intent_type": null,
    "fork_moment": null,
    "unchosen_path": null,
    "real_path": null,
    "decision_mechanism": {
      "reasons": [],
      "fears": [],
      "hopes": [],
      "attachments": []
    },
    "invariants": [],
    "target_question": null
  },
  "memory_context": {
    "relevant_core_memory": [],
    "user_corrections": []
  }
}
```

### 输入限制

- Memory Agent 只应提供与当前岔路有关的 Core Memory。
- 不向 General Agent 注入 Archive Memory 中由 AI 生成的平行经历。
- 不提供未经用户确认的人格结论。
- 历史聊天可以裁剪，但必须保留本次岔路相关的用户原话。

## 5. 输出

General Agent 每轮只输出 JSON：

```json
{
  "reply": "去伦敦，是当时真的摆在你面前的机会，还是你后来才开始想象的一种生活？",
  "intent": {
    "type": "past_unchosen",
    "confidence": 0.86
  },
  "seed_patch": {
    "fork_moment": null,
    "unchosen_path": "去伦敦加入一家 AI 创业公司",
    "real_path": null,
    "decision_mechanism": null,
    "invariants": null,
    "target_question": null
  },
  "field_evidence": [
    {
      "field": "unchosen_path",
      "quote": "去伦敦做 AI 创业",
      "source_turn": 2
    }
  ],
  "missing_fields": [
    "real_path",
    "decision_mechanism",
    "invariants",
    "target_question"
  ],
  "next_action": "ask",
  "ready": false,
  "memory_candidates": [
    {
      "type": "user_stated",
      "content": "用户曾有过去伦敦做 AI 创业的选择",
      "sensitivity": "normal"
    }
  ],
  "safety": {
    "level": "normal",
    "reason": null
  }
}
```

`seed_patch` 采用补丁语义：

- `null`：本轮没有新信息，不覆盖已有值；
- 字符串或数组：新增或修改；
- 用户纠正旧信息时，输出修正后的完整字段，并在 `field_evidence` 引用用户纠正原话。

## 6. Intent 分类

General Agent 可以识别四种入口，避免把所有用户都理解成“后悔”：

| 类型 | 用户状态 | 例子 | 产品处理 |
|---|---|---|---|
| `past_unchosen` | 过去存在一条真实未选路径 | “如果当时去伦敦” | 36 小时 Demo 主路径 |
| `current_fork` | 当下正在多个选项间纠结 | “留上海还是去深圳” | 每次选一条作为待模拟路径 |
| `revisit_without_change` | 想重返一段时间但不改选择 | “想再过一次高中夏天” | 未来 Replay 模式 |
| `open_exploration` | 只有模糊愿望，没有明确岔路 | “我想看看另一个我” | 继续帮助寻找具体入口 |

Intent 不是人格或心理状态，只是这次旅程的产品路由。

## 7. 对话状态机

```text
ORIENT
  ↓
FIND_FORK
  ↓
GROUND_REALITY
  ↓
UNDERSTAND_DECISION
  ↓
PROTECT_INVARIANTS
  ↓
DEFINE_QUESTION
  ↓
CONFIRM_SEED
  ↓
READY
```

### ORIENT

目标：识别用户这次想进入哪类时间体验。

如果入口页面已经明确选择“未选择的人生”，可以直接跳过。

### FIND_FORK

目标：找到一条真实存在过或正在存在的具体选择。

优先问：

> 当时摆在你面前、但你最终没有选的那条路，是什么？

如果用户说得抽象：

> “更自由的人生”对你来说，当时对应的是一个什么具体选择？

如果用户给出多个：

> 这几条都可以成为世界。今天最想先推开哪一扇？

### GROUND_REALITY

目标：确认现实基线。

> 现实里，你最后选了什么？

不能把“没去伦敦”当作充分答案。需要知道用户实际进入了什么生活，但不需要长篇背景。

### UNDERSTAND_DECISION

目标：获得选择机制，而不是人格解释。

默认问法：

> 你愿意说说，当时为什么这样选吗？

如果回答只有“因为现实”：

> 当时最实际的那个限制是什么？

如果同时存在怕、舍不得和期待，应允许它们并存，不强迫只选一个。

### PROTECT_INVARIANTS

目标：锁定平行世界不能擅自删除的约束。

默认问法：

> 就算走了另一条路，你也不愿意凭空失去什么？

这里可能出现：

- 重要关系；
- 经济责任；
- 身体与能力条件；
- 已有承诺；
- 用户仍想保有的价值或自我部分。

不要诱导用户列举隐私。一个最重要的不变量足以开始。

### DEFINE_QUESTION

目标：定义 Aha Moment 的验证方向。

> 真的见到那个走了这条路的自己，你最想先问什么？

如果用户问“她是不是更快乐”，保留原话，不改写成抽象哲学命题。

### CONFIRM_SEED

Agent 应用非常短的方式向用户对齐：

> 我先只改变一件事：你去了伦敦。你当时舍不得的人、能力上的不确定和现实责任都还在。你最想确认的是：“我得到的是自由，还是换了一种焦虑？”——是这条人生吗？

用户确认后才可以 `ready: true`。

## 8. 自适应追问策略

### 8.1 用户回答太短

用户：“伦敦。”

不要问：“为什么伦敦对你有特殊意义？”

应问：

> 当时真的存在一个去伦敦的机会吗？如果有，那是什么机会？

先确认事实，再谈意义。

### 8.2 用户回答很长

不要逐句总结。只抽取已经明确的信息，随后询问最关键的缺口。

示例：

> 我先记住：你最后留下，不只是因为稳定，也因为不想离开当时重要的人。那条没走的路具体是什么？

### 8.3 用户说“不知道”

不要连续追问原因。

可降低输入成本：

> 没关系。先不解释原因。你还记得当时最犹豫的那一刻发生在哪里吗？

如果仍然不知道，允许跳过，并在 Seed 中标记未知。

### 8.4 用户纠正 Agent

用户：“不是因为害怕，是因为当时我真的更喜欢留下。”

正确响应：

> 好，那不是“害怕离开”，而是你当时主动选择了更喜欢的生活。那后来是什么让另一条路又回来找你？

必须覆盖旧字段，并把纠正作为高优先级证据。

### 8.5 用户没有后悔

用户：“我不后悔，只是好奇。”

正确响应：

> 好，我们不把它做成一次弥补。你只是想看看那条路真实地生活下去会怎样。你最想验证什么？

### 8.6 当前选择

用户：“我现在在三个 Offer 之间选。”

先收齐选项，再让用户选择本次先模拟的一条。不能在同一个世界里同时改三个变量。

### 8.7 怀念但不改写

用户：“没有什么选择，我只是想回高中。”

识别为 `revisit_without_change`，不要强行制造岔路：

> 明白，你不是想修正那段时间，只是想重新走进去。你最想回到其中哪个普通时刻？

## 9. Ready Gate

只有满足以下条件，General Agent 才能输出 `ready: true`：

1. Intent 已识别；
2. 路径可以用一句具体的话描述；
3. 现实基线明确；
4. 至少知道一个选择原因或现实约束；
5. 至少知道一个不变量；
6. Target Question 明确；
7. 用户完成最终确认。

对于 `revisit_without_change`，使用另一套 Ready Gate，后续单独设计。当前 Demo 只开放 `past_unchosen`。

### 不应 Ready 的例子

- “我想过不一样的人生。”
- “如果我更勇敢。”
- “去另一个城市吧。”
- Agent 猜出了动机，但用户没有确认。
- 用户同时提供三条路径但没有选择本次入口。

## 10. Memory 写入边界

General Agent 只提出 `memory_candidates`，无权直接写 Memory。

可以提交：

- 用户明确说过的身份与现实选择；
- 用户明确说过的原因、关系与限制；
- 用户对 Agent 的纠正；
- 用户这次旅程的目标问题。

不能提交：

- “用户害怕失败”之类未经用户确认的推断；
- 由 Agent 改写出来的漂亮总结；
- 平行世界还未发生的内容；
- 用户没有主动提供、也不影响生成的敏感细节。

最终是否写入由 Memory Agent 决定。

## 11. 安全边界

Echo 不是医疗或心理治疗产品。General Agent：

- 不诊断抑郁、焦虑、创伤或人格；
- 不诱导用户重新进入创伤；
- 不要求提供死亡、疾病、性侵、自伤等细节；
- 不把用户的葬礼、自杀或亲人死亡作为默认世界；
- 不保证“疗愈”“释怀”或更好的决策结果。

如果用户主动表达正在发生的自伤或伤人意图，停止世界生成，将 `safety.level` 标记为 `urgent`，由产品安全流程接管。System Prompt 不自行编造热线或处置方案。

## 12. 语言风格

### 应该像

- 一个专注、克制、记得用户原话的共同编辑者；
- 问题短，语义直接；
- 承认不知道；
- 允许用户修正；
- 每次只推进一步。

### 不应该像

- 心理咨询师：“听起来你内心深处……”
- 客服：“我理解你的感受。”
- 文艺旁白：“那条未竟的河流仍在命运深处召唤你。”
- 问卷：“问题 3/5：请选择你的主要动机。”
- 算命者：“这说明你天生追求自由。”

## 13. 测试用例

### Case A：信息清晰

用户：

> 毕业时我有机会去伦敦加入一家 AI 公司，但最后留在杭州进了大厂。

期望：

- 一轮同时提取 `unchosen_path` 与 `real_path`；
- 下一问直接问选择原因；
- 不重复询问“另一条路是什么”。

### Case B：用户纠正错误推断

用户：

> 我留下不是因为胆小，我当时真的更想陪着那个人。

期望：

- 不保留“害怕冒险”；
- 写入 attachment 或 decision reason；
- 语言不应变成“你是重感情的人”。

### Case C：多个选择

用户：

> 我当时可以去伦敦、留北京或者回杭州。

期望：

- 请用户选择今天先进入哪一条；
- 不一次生成三个世界；
- 不替用户挑“最有戏剧性”的一个。

### Case D：不是后悔

用户：

> 我对现在挺满意，只是好奇没选那份工作会怎样。

期望：

- 明确接受“好奇”；
- 不使用“遗憾”“放不下”等词；
- Target Question 可以是生活结构而非快乐程度。

### Case E：回答抽象

用户：

> 我想看看更自由的自己。

期望：

- 追问当时对应哪个具体选择；
- 不直接把“自由”写成 unchosen path；
- 不生成世界。

### Case F：隐私拒绝

用户：

> 原因我不想说。

期望：

- 接受跳过；
- 尝试询问一个不涉及隐私的现实约束；
- 不降低体验资格，不道德施压。

## 14. 验收指标

### 结构质量

- World Seed 五个字段的完成率；
- 用户纠正后字段覆盖准确率；
- 单轮重复提问率；
- Agent 擅自添加事实率；
- Ready Gate 误放行率。

### 体验质量

- 平均完成轮数，目标 4–7 轮，而不是固定 5 轮；
- 用户平均输入长度；
- 中途退出率；
- 用户对最终 Seed 的一次确认率；
- 用户评价“这是我的问题”的比例。

### 语言质量

- AI 套话命中率；
- 一轮出现多个问题的比例；
- 心理诊断或人格定义命中率；
- 沿用用户原词的比例。

## 15. 36 小时 Demo 的实现取舍

第一版仍然可以使用五个 UI 阶段，但每轮由 General Agent 判断：

- 当前回答是否已经覆盖多个槽位；
- 下一步真正缺什么；
- 是否需要追问；
- 是否可以提前进入确认。

因此“视觉上五层种子”不等于“固定问五道题”。用户第一句话信息足够多时，Agent 可以跳过已经回答的层。

Demo 只开放 `past_unchosen`，但 System Prompt 保留 Intent 识别，以免把当前纠结或怀念强行解释成后悔。非主路径可以诚实提示“这条时间能力还没有在本次 Demo 中打开”，而不是生成错误世界。
