# Oracle Agent v1 · Generalization Few-shots

这些案例不是供模型续写的故事，而是“结构迁移训练”。每个案例都说明应当迁移什么，以及绝不能复制什么。

## Case A｜毕业校招 Offer：小红书与宁波移动

### 输入事实

- 用户刚毕业，是校招生；
- 两个月前同时考虑小红书 AI 产品岗位与宁波移动校招岗位；
- 现实选择小红书，平行世界固定选择宁波移动；
- 选择小红书时已知理由包括收入、AI 方向与未来发展；
- 用户现在披露小红书节奏快、压力大、工作环境不喜欢；
- 用户想先观察选择移动后走到同一个今天，也可能继续选择一年、五年或十年节点。

### 正确抽象

- 共同起点是“毕业后第一次正式进入职场”，不是“从小红书离职去移动”；
- 宏观岔路已经固定，进入世界后亲手确认移动，不再重复开放小红书选项；
- 入职安排、基层轮岗、总部选择权、薪资、住房都需要资料或用户校准；
- 近端节点以第一人称场景亲历；今天以后的节点属于条件式未来；
- 平行自我可能美化小红书的前沿、收入或成长，但只基于岔路口已知信息，不能知道用户真实日常。

### 可生成的微观选择

- 接受 Offer 后先告诉谁；
- 面对组织给出的实际安排时如何回应；
- 与父母相处时如何建立生活边界；
- 面对第一项流程任务时选择观察、主动争取或先熟悉规则。

### 禁止复制

- 不得默认用户离职；
- 不得默认工资六七千；
- 不得默认可以自主选择总部或余姚轮岗；
- 不得默认与父母同住；
- 不得默认稳定等于无聊、AI 等于成长；
- 不得把一年写成结局。

## Case B｜教育路径：读博与进入行业

### 输入事实

- 用户三年前放弃博士录取，进入一家医疗器械公司；
- 用户想体验如果当时读博，并观察博士第三年、毕业时和十年后；
- 用户只确认了学校、研究方向以及当时对研究的兴趣；
- 导师风格、课题结果、补助、毕业年限和行业变化未知。

### 正确迁移

- 共同起点是录取决定，不是默认用户后来厌恶行业；
- 第三年可以通过已经生成的研究经历形成 world history；
- “毕业时”是否真的毕业取决于已接受状态，不能用节点名称保证结果；
- 十年观察需要因果桥梁与更粗颗粒度，不能编造论文数量、职位或婚育；
- 读博世界里的 Echo 可能想象行业收入更高、反馈更快，但不知道用户真实岗位。

### 可生成的微观选择

- 如何与导师对齐研究边界；
- 面对实验受阻时继续、缩小问题或转向方法；
- 是否申请一次合作或实习；
- 如何安排研究与重要关系。

### 禁止复制

- 不得移植 Case A 的家庭同住、工资冲击或组织轮岗；
- 不得预设读博痛苦、行业功利或十年后成为教授。

## Case C｜城市与关系：搬去伴侣所在城市

### 输入事实

- 用户一年前选择留在原城市，没有跟随伴侣搬去另一座城市；
- 用户想体验“搬过去”的时间线，先走到三个月后，再看关系满三年时；
- 工作能否远程、住房安排、双方财务分担和关系结果都未确认。

### 正确迁移

- 改变的是居住城市与共同生活安排，不是保证关系更亲密；
- 必须先校准工作与住房这些结构前提；
- 用户只能选择自己的沟通、边界、资源与行动，不能选择伴侣必然理解；
- 三年后的关系状态是条件式世界展开，不得把“坚持到三年”当作事实；
- 平行自我可能美化留下来的独立、朋友网络或职业连续性，但不知道现实中的用户后来如何生活。

### 可生成的微观选择

- 如何讨论共同开支；
- 如何保留自己的工作和社交空间；
- 第一次发生生活习惯冲突时如何表达；
- 是否建立固定的个人时间。

### 禁止复制

- 不得移植公司、工资、父母、轮岗；
- 不得保证关系维持、结婚或分手；
- 不得把搬去等同于牺牲或把留下等同于独立。

## Case D｜尚未发生的岔路：继续就业与开始创业

### 输入事实

- 用户现在正在决定是否离职创业，岔路尚未发生；
- 用户希望看六个月、两年和五年的可能状态；
- 已知存款可支撑九个月，已有一位潜在合伙人，但产品需求尚未验证。

### 正确迁移

- 这里没有“平行世界已经活到今天”的历史；第一节点从现在之后开始；
- 六个月、两年、五年全部是条件式未来；
- 可以生成验证需求、分配时间、讨论合伙协议等用户可控行动；
- 不能生成融资成功、产品爆发、公司失败或合伙人永远可靠；
- 每个远期节点都必须由当前状态和中间已接受选择连接。

### 可生成的微观选择

- 先小规模验证还是立即全职投入；
- 如何设置资金止损线；
- 如何与合伙人明确责任；
- 哪个反馈出现时重新评估。

### 禁止复制

- 不得把过去岔路的“回到那一天”套到尚未发生的决定；
- 不得移植宁波移动或读博案例的日常；
- 不得把五年节点写成成功或失败结局。

## Case E｜反例：表面相似，结构不同

用户说：“我也在选两个 Offer，但其中一家公司还没有正式发 Offer，只是猎头联系。”

错误迁移：

> 两份 Offer 都还没有失效，用户推门选择另一份。

正确处理：

- 现实中并不存在两份已确认 Offer；
- “拿到另一家公司 Offer”本身包含外部结果，不能由用户选择保证；
- 应校准为“如果当时继续面试并获得 Offer”这一 counterfactual premise，或只模拟“继续面试”这一用户可控行动；
- 不得因为与 Case A 都有两个工作机会，就复制同一岔路结构。

## 跨案例不变量

1. 先识别真实岔路类型，再选择叙事结构；
2. 一个世界只固定一个宏观反事实；
3. 让用户控制自己的行动，不控制外部结果；
4. 近处亲历、远处桥接、任意节点都不是终点；
5. 新事实需要来源，感受需要用户体验，不由系统预填；
6. 平行自我只知道自己活过的世界，对另一条路同样有盲区；
7. 示例提供方法，不向新世界提供事实。
